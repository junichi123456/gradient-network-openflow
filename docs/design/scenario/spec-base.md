# シナリオ実装仕様書(草案)

Oct 31, 2026 · @jun

## 1. 目的と範囲

シナリオ台本(チャート1〜30+補完31〜35+追加枠36〜)を、Godot 4.3 C#の既存ゲームに実装するための仕様。台本が「何を描くか」、本書は「どうデータ化し、どう動かすか」を定める。

- **実装する**: 20本編チャート+エンディング、35ダンジョン(本編30+補完5)、16体のMBTI話者、振り分けチュートリアル、主人公・相棒の選出、ハコニワの成長と住民登場、会話・イベント基盤、進行セーブ、クリア後の追加ダンジョン。
- **今回は実装しない**: 小説化用の長文(台本側の仕事)、補完チャート21〜30の会話本文(枠だけ用意)、追加枠36〜44の本編(枠・解放条件のみ)、立ち絵・BGM・演出アセット(仮素材で可)。
- **文体の原則**: 会話本文はコードに書かず `Data/story/` のJSONに置く。台本の言い回しは「ベース文」として入れ、MBTI語尾の自動変換はやらず、話者ごとに手で書く(16体表は台本の語尾ガイドを正とする)。
- **段階導入**: 1チャート=1PRで縦に通す。第1段階は「チャート1(ビーチのどうくつ)が最初から最後まで遊べる」ことをゴールにする。

調査済みの事実と、台本とぶつかる箇所。`Scripts/` 配下を基準に書く。

## 3. データ設計

すべて `Data/story/` にJSONで置き、起動時に `StoryDatabase`(新規、`SpeciesDatabase` と同じ読み方)が一括ロードする。IDは文字列で、参照切れ(存在しない種族ID等)は起動時にエラーを出す。

| ファイル | 中身 | 主なキー |
| --- | --- | --- |
| `charts.json` | チャート1〜44+の定義 | `id`("c01"〜"c35","x36"〜)、`part`(1〜4)、`kind`(main/supplement/extra)、`title`、`unlock`(前提チャート・フラグ)、`dungeons[]`、`events[]`(§5のイベントID順)、`hub_changes[]`(§8) |
| `dungeons.json` | 35本+追加枠 | `id`、`chart`、`name`、`floors`、`rule_id`(既存 `Data/dungeons.json` を参照)、`end_type`(既存enum)、`boss`(BossSpec)、`scenario_fight`(任意)、`wild_pool_ref` |
| `characters.json` | 16体の話者+名前付き16人 | `id`、`species_id`、`display_name`、`mbti`、`first_chart`、`role`、`speech_style`(語尾・一人称。ゼノグリフは「わたしたち」) |
| `pal_plan.json` | 287種の登場計画 | `species_id`、`first_chart`、`dungeons[]`、`wild`(bool)、`category`(normal/legendary/nonwild)、`recruit_rule` |
| `events/<chart>.json` | チャートごとの会話・演出 | §5 |
| `selection.json` | 振り分け | 4問、各選択肢の16タイプへの加点、タイプ→種族の表(§6) |

**初期データの作り方**: `pal_plan.json` は既に作成済みの `pal_appearance_plan.csv`(287行)を変換して作る。CSVとの差分を実装前に直す: (a) 伝説5体の「クリア後(31〜37)」→「36〜42」、(b) 補完ダンジョン5本(チャート31〜35)を「出現ダンジョン」列に反映。初登場チャートは変わらない(補完ボスは登場済みのパルから選んだため)。

**BossSpec**: `species_id` / `level` / `hp_mult` / `atk_mult` / `defeat_ok`(trueなら負けても進行) / `group`(群れ戦の場合の構成リスト) / `post_battle`(「戦闘後に共闘」「会話イベントID」)。レベル曲線はチャート1→Lv5、チャート20→Lv60を仮置きして線形補間(調整は実装後のプレイで)。

## 4. 進行管理とセーブ

**StoryState**(新規、独立した純粋データクラス。Godot非依存にしてヘッドレスでテスト可能にする):

- `CurrentChart`(最後に開始した本編チャート)、`CompletedCharts`(集合)
- `Flags`(文字列集合)、`Counters`(文字列→整数)
- `Protagonist` / `Partner`(種族ID。選出後に確定)、`ProtagonistIntrovertion=85`
- `ClearedDungeons`、`ResidentsArrived`(住民ID集合)
- `ChoicePath`(守る/譲る/継ぐ、チャート16〜19で確定)、`PostClear`(bool)

**チャート進行の規則**:

1. チャートは `unlock` の全条件が真になると「開始可能」。開始はハコニワのイベントトリガーか、ダンジョン選択画面の「物語」マーク付き項目。
2. チャートの「踏破ダンジョン」を全てクリアし、締めのイベントを見終えると完了。完了時に次チャートの `unlock` を再評価。
3. 補完31〜35は「本編N完了後、N+1開始前」に挿入し、1回スキップ可能。スキップしても本編は進むが、クリア後に回収できる。
4. 補完21〜30はハコニワの住民イベント(一度きり・経過日数・親密度で解放)。
5. クリア後(エンディング後)は `PostClear=true` になり、追加枠36〜44が開く。

**セーブ**:

- `SaveService`(新規、純C#、`user://save_slot_1.json`)。形式は `{ "version": 1, "story": {...}, "hub": {...}, "party": {...}, "inventory": {...} }`。
- 保存タイミング: ダンジョン踏破時、ハコニワへ戻った時、チャート完了時。ダンジョンの途中は保存しない(中断セーブは今回の範囲外)。
- `HubUpgradeManager` の施設レベル・素材・パーティをスナップショット化する `ExportState()` / `ImportState()` を追加。`Pending*` で引き渡しているダンジョン中の値は保存対象外。
- `version` が違うセーブは読まず「互換性なし」を表示。マイグレーションは初版では作らない。

## 5. イベント・会話システム

台本の「流れ」を、イベントの列としてデータ化する。イベントエンジンは、列を上から順に実行する単純なインタプリタにする。

**イベント定義(例)**:

```json
{
  "id": "c03_e02",
  "trigger": { "type": "hub_enter", "requires": ["c02_done"], "once": true },
  "steps": [
    { "op": "say", "who": "violetta", "text": "..." },
    { "op": "say", "who": "protagonist", "text": "...", "face": "quiet" },
    { "op": "choice", "options": [{"text": "...", "set_flag": "c03_trust"}] },
    { "op": "give_item", "id": "mysterious_shard", "n": 1 },
    { "op": "unlock_dungeon", "id": "d05_smoke_road" },
    { "op": "set_flag", "flag": "c03_done" }
  ]
}
```

**実装するop(初版)**: `say`(話者・本文・表情)、`narration`、`choice`、`set_flag` / `inc_counter`、`give_item`、`unlock_dungeon`、`start_scenario_fight`(§7)、`join_resident`(§8)、`fade`、`wait`、`goto_chart`、`if`(flag条件で分岐)。追加はop名を増やすだけで済むように、ハンドラを辞書登録式にする。

**トリガー種**: `hub_enter` / `dungeon_clear` / `dungeon_floor`(階到達で発火) / `boss_defeated` / `chart_start` / `chart_end` / `time_passed`(ハコニワ日数)。

**UI**: `StoryDialogueUI`(新規、下部メッセージウィンドウ+名前欄+立ち絵枠)。文字送り、決定で全文表示、オート送り、ログ表示。立ち絵が無い間は種族のスプライトをそのまま使う。

**話者の語尾**: `characters.json` の `speech_style` を仮名の表示には使わず、本文は最初から語尾込みで書く。`speech_style` はレビュー・校正の基準としてのメタデータ(テストで「話者の語尾リストが本文に出ているか」を粗く検査する程度)。

**主人公の台詞**: 主人公は内向度85の設定なので、発言は短い。このゲームでは主人公が話す行は、すべて `{protagonist_voice}` テンプレートとして主人公タイプ別の語尾で差し替えてよい(§10の未決事項)。

## 6. 振り分けチュートリアルと主人公・相棒の選出

**プレイアブル16体とID**(`Data/species.json` で確認済み): モコロン001、ツッパニャン002、クルリス004、カモノスケ005、チョロゾウ011、ポチムネ013、パチグリ015、ンダコアラ016、ネムラム022、エテッパ023、ルナティ024、ニャオテト027、チルテト027B、ユキツネ029B、モグルン031、ボルトラ042。

**流れ**:

1. タイトル→「はじめから」→ 夢のシーン(暗転、影が16体、プレイヤーはシルエットしか見えない)。
2. 4問の二択。問いは「E/I、S/N、T/F、J/P」に1問ずつ対応し、選択肢の文言はMBTI用語を出さない情景の問いにする(例: 「静かな川べと、にぎやかな広場、行くのは」)。
3. 4軸の結果(16タイプ)→ `selection.json` の表で主人公の種族が決まる。表は台本の対応(INFJ ルナティ、INFP ネムラム、INTJ ユキツネ、INTP モグルン、ISFJ モコロン、ISFP ンダコアラ、ISTJ ポチムね、ISTP チルテト、ENFJ クルリス、ENFP パチグリ、ENTJ ニャオテト、ENTP ボルトラ、ESFJ エテッパ、ESFP カモノスケ、ESTJ ツッパニャン、ESTP チョロゾウ)をそのまま使う。
4. 主人公の種族はこの時点では表示せず、チャート1の「水面に映る姿」イベントで初めて見せる。
5. **相棒選定**: 主人公と別属性のプレイアブルから、さらに互いに属性が違うように3体をランダム抽出して候補とする(プレイアブル属性は無/草/水/電/氷/地/闇/虚。主人公を除くと常に7属性残るので3属性抽出は必ず成立する)。乱数は `StoryState` にシードを保存して再現可能にする。
6. 3体の中から1体を選ぶ。選んだ種族が `Partner`。選ばれなかった14体はチャート2〜5でハコニワ住民として登場させる(属性判定と独立。住民の召喚順は§8)。

**ステータスの差**: 主人公は内向度を `ProtagonistIntrovertion=85` で固定。相棒は種族ごとの標準の内向度(主人公より低い)をそのまま使い、感情表現の豊かな台詞を割り当てる。内向度が戦闘仕様に影響するかは§10で確認(初版は台詞の長さと間のみに使う)。

**コード変更**:

- `Entities/PartyManager.cs`: 相棒"001"のハードコードをやめ、コンストラクタで初期編成(主人公・相棒)を受け取る。`MaxActiveParty=2` は維持。
- 主人公は「入れ替え不可・必ずパーティ先頭」フラグ `IsProtagonist` を持つ。相棒は入れ替え不可ではないが、シナリオイベント中は強制同行をする `StoryLock` を設ける。
- `Scripts/Story/SelectionScene`(新規)と、これを起動するタイトル経路(セーブが無いときのみ)。

## 7. ダンジョン・ボス・野生出現の仕様

**ダンジョン一覧**は台本の「踏破ダンジョンとボス」35行表をそのまま `Data/story/dungeons.json` へ転記する(コピー元は台本の表。二重管理になるので、実装後は JSON を正とする)。階数・ボス種族は表の値。

**終端種ごとの実装**(`Dungeon/FloorController.cs` の `GenerateFinalFloor()` の分岐):

| ダンジョン | `DungeonEndType` | 実装すること |
| --- | --- | --- |
| 通常のボス(上表の大半) | `FreeDungeonBoss` | **既存のまま**。`BossEntity` が `BossSpec` を受け取るようにするだけ |
| ハコニワ裏山(ヘルガルダ)、世界樹の根もと(セイントール) | `StoryBoss` | `defeat_ok=true`。HPが一定以下、またはパーティ全滅でイベントに切り替え、クリア扱いでハコニワへ戻す(ペナルティなし) |
| 群れ戦(ささやきの洞: ゼノベーダ複数+ゼノルーダ複数) | `StoryMultiEnemyBattle` | `BossSpec.group` の全員をボス部屋に同時配置。全員撃破でクリア。難易度は、単体ボスの合計ステータスを超えないように `hp_mult` で下げる |
| ボス無し到達クリア(海辺や読み物系の補完ダンジョンなど、必要なときだけ) | `FreeDungeonNoBossFinalFloor` | `EscapePortal` に到達でクリア |
| イベントだけで終わる最終階 | `StoryNoBossFinalFloor` | `_storyEventCompleted` をイベント側から立てる。初版では使わない想定 |

**シナリオバトル**は「ボス部屋に入った」「ボスHPがN%になった」「ボスを倒した」「パーティ全滅した」でイベントを呼べる。これを `BossSpec.hooks` として持つ。「戦闘後に共闘」(スザク)は、ボス撃破後に対象をパーティへ一時加入させ、次のダンジョンで同行する形。

**野生出現**: `pal_plan.json` の `first_chart` 以降、`dungeons[]` に含まれるダンジョンで野生として出現可能になる。`wild=false` の種族(非野生16種)は常に出現しない。伝説7種はクリア後(`PostClear`)の追加枠でだけボスとして登場し、勧説のチャンスを判定する(確率は→§10)。

**非野生16種の扱い**: 7体の伝説と九体のボスパル(シャオロン、ヒョウガオー、レジェンディア、ベラルージュ、ベラノワール、ゼノグリフ、ゼノドラン、ゼノベーダ、ゼノルーダ)。クリア後の「再挑戦回廊(追加枠43)」でのみ、その9体を再度ボスとして相手にでき、勧説の対象にもなる。

## 8. ハコニワ拠点の成長と人物登場

- 拠点の施設・見た目の変化は `charts.json` の `hub_changes[]` で宣言する(例: チャート5完了で「作業台」解放、チャート8で「冒険者の宿」)。`HubUpgradeManager` の既存施設レベルとは別物とし、シナリオ側の変化は「見た目のフラグ」を立てるだけに留める(施設の効果は既存の素材消費に任せる)。
- 住民は `join_resident` op で登録。登録された種族はハコニワで立ち話す。会話はチャートごとの「住民会話セット」を引き、同じセットを繰り返しても常に同じ話になるようにする(ランダム会話は後回し)。
- 選ばれなかった14体のプレイアブルは、チャート2〜5のうちにバラして登場させる(后半にあるチャートに偏らないように、属性ごとに1チャートに1〜4体)。
- 名前付き16人の「いつ、どこにいるか」は `characters.json` の `first_chart` と、ハコニワ常駐かどうかの `resident_from` で管理する。ヒントとして、ヘルガルダ・ブシガエルはチャート2で定住、ヴィオレッタはチャート3から研究施設長。
- クリア後は、再挑戦で仲間になったパルをハコニワの住民として表示する拡張を候補とする(初版のスコープ外)。

## 9. 実装フェーズと検証

各フェーズは独立したPR。完了条件はCLAUDE.mdのヘッドレス回帰テスト(現状153項目)が全て通ること+下記の追加項目。

| フェーズ | 内容 | 検証(期待値) |
| --- | --- | --- |
| P0 基盤 | `StoryState`、`StoryDatabase`、`SaveService`(§3・§4)。データは仮でチャート1件だけ | StoryState→JSON→StoryStateの往復で全フィールド一致。参照切れのIDを入れたデータで起動時エラー |
| P1 イベント基盤 | イベントインタプリタ、`StoryDialogueUI`、トリガー発火、一度きり管理 | ヘッドレスで、同じイベントを二回発火して二回目は何も起こらないこと、`if` 分岐がフラグどおりに選ばれること |
| P2 チュートリアル | §6の振り分け・相棒選定、`PartyManager` の固定廃止 | 16タイプ全てで主人公種族が台本の表どおり。任意の主人公に対して候補3体の属性が互いに異なり主人公とも異なること(16タイプ×乱数シード多数で総当たり) |
| P3 チャート1〜2 | ビーチのどうくつ、ハコニワ開始、ヘルガルダ戦(`StoryBoss`) | チャート1を開始→クリア→チャート2開始可能。ヘルガルダで全滅しても進行フラグが立つ |
| P4 ダンジョン拡張 | `dungeons.json` 35本、`BossSpec`、`DungeonDestinations` をデータ駆動に | 35本すべてでヘッドレスが「生成→最終階到達→ボス種族が表どおり」を確認 |
| P5 群れ戦・共闘 | `StoryMultiEnemyBattle`、戦闘後共闘(スザク) | 群れ戦で全員撃破するまでクリアしない。共闘パルが次のダンジョンで同行 |
| P6 本編チャート3〜20 | 1チャートずつ会話・イベントをデータ化。守る/譲る/継ぐの分岐(§10) | チャート1〜20を連続で進める「全クリアシミュレータ」テスト(イベントをスキップで進め、ボスは即撃破扱い)でエンディング到達 |
| P7 補完31〜35 | 5本の挿入チャートとダンジョン | スキップしても本編が進む。クリア後に回収できる |
