## 0. ユーザー要求と確認結果

初版の要求（原文）:

```
範囲技の威力を-10〜-20します。また、場合により命中を-5することも許容します
```

改訂の要求（原文）:

```
物理の範囲技は今回の対象に含めません。特殊の範囲技のみ対象とし、同属性の範囲技は1~3個までとし、
威力グリッドから超過する分は削除するものとします。learnsetの規則における評価は、範囲技のうち部屋対象を+25、
範囲対象を+15、周囲対象を+10として評価するものとします。
```

確認の結果（確定）:

1. 威力・命中は**点で引く**（威力 -10〜-20、命中 -5）。範囲技 = 射程が 部屋 `Room`・範囲 `Area`・周囲 `Surrounding`。
2. **対象は特殊の範囲技だけ**。物理の範囲技（ディスチャージパンチ `MV_170`、電・部屋・威力60 の1件）は対象外。
3. 個数は**属性ごとに 部屋＋範囲＋周囲 の合計**で数える。
4. **削除数を優先する（約15個）。「1属性3個」の上限は目安**として扱い、厳密には守らなくてよい。→ 本書は**ちょうど15個**を削除する（§5-2）。
5. 削除する技は**威力が高い技から残す**。`Data/moves.json` から技ごと消す（learnset の該当行も消える。代わりの技は足さない）。
6. 威力 -10〜-20 の引き下げは**削除と併用**。残った特殊の範囲技に適用する。命中 -5 も従来どおり許容。引き下げ幅は削除後に小さな対照実験（各 3,000 試合、逐次）で決める。
7. learnset 規則での範囲技の評価は**引き下げ後の実際の威力＋加算（部屋 +25／範囲 +15／周囲 +10）**。
8. 対照実験は各候補 3,000 試合（`--random --matches 750 --out` を4プロセス並列）。-15 から測り、結果を見て次を決める逐次方式。最終の採用案だけ §31 の前後比較表を作る（基準は §30-6 の 10,000 試合）。

## 2. 現状（実装者向けの要約）

### 2-1. 分析で分かったこと（§30-6 の 10,000 試合と、その追加分析）

| 攻撃区分 | 補正後pt（突破値・気質の自動配分あり、§30-6） | 配分なし |
|---|---|---|
| 物理攻撃 | -3.4 | -3.3 |
| 特殊攻撃 | **+5.1** | +4.7 |
| 両刀攻撃 | -2.8 | -1.5 |

（補正後pt = 出場1回ごとの勝率 − BST6 差ロジスティックによる期待勝率。突破値・気質の寄与は約 0.4pt で原因ではない。）
個体ごとの勝率残差の回帰で、攻撃区分だけのモデル（R² 0.350、物理 -1.8／特殊 +6.2）に、技の性質を加えたモデル（R² 0.454）では物理 +3.2／特殊 +2.7 に縮む。
効いていたのは**範囲率（攻撃技のうち射程が Room/Area/Surrounding の割合）で、100%あたり +30pt**。特殊攻撃の個体は範囲率が約19%、物理攻撃は約2%。
属性別の補正後差は -3.1〜+2.1pt。範囲技は4対4で複数の相手に当たるのに威力が単体技と同等（特殊技の平均威力: 単体 Adjacent 73.9・範囲 Area 74.3・部屋 Room 69.2・直線 Line 53.7）。

### 4-1. 1回の計測（1候補 = 3,000 試合）

```sh

  godot --headless --path . Scenes/BattleMatchScene.tscn -- --random --matches 750 --out $O/cut${D}<acc>_r<回>_$k.csv &
done; wait
for by in offense role element; do
  python3 Tools/analyze_random_by_element.py $O/cut${D}<acc>_r<回>_*.csv --by $by --bootstrap 200
done
python3 Tools/analyze_random_by_element.py $O/cut${D}<acc>_r<回>_*.csv --by defense   # 参考
```

### 4-3. 3,000 試合の標準誤差と境界の扱い

3,000 試合の出場数は §30-6 の約 0.3 倍。勝率の標準誤差を `0.5/√n`×(設計効果 ≈1.5 の平方根 ≈1.22) で見積もると:

| 区分 | 出場数（3,000試合） | SE（試算） |
|---|---|---|
| 物理攻撃 | ≈11,600 | ≈0.6pt |
| 特殊攻撃 | ≈9,200 | ≈0.65pt |
| 両刀攻撃 | ≈2,900 | ≈1.1pt |
| 役割9 | ≈800〜4,300 | ≈0.9〜2.2pt |
| 属性10 | ≈2,000〜4,000 | ≈1.0〜1.4pt |

判定には `--bootstrap 200` の実測 SE を使う:

- 各行で `| |補正後pt| − 基準 | < SE` なら**境界**。
- 全行が境界でなく基準内 → **合格**。境界でない行が1つでも基準外 → **不合格**。
- 境界の行があり、他に基準外の行が無い → 同じ案を同条件で**もう 3,000 試合**測り、計 6,000 試合の合算の点推定で決める（再計測は1候補1回まで、合算後は境界判定をしない）。
- 2案が合格したら**変更幅の小さい方**を採る（-10 < -15 < -20 < -20＋命中-5）。

### 4-4. 逐次の手順

攻撃区分の不合格を向きで分ける:

- 「不足」= 特殊攻撃 > +3、または 物理攻撃・両刀攻撃のいずれかが < -3（かつ「過補正」に当たらない）。
- 「過補正」= 特殊攻撃 < -3、または 物理攻撃・両刀攻撃のいずれかが > +3（かつ「不足」に当たらない）。
- 両方に当たる → 停止して報告。

1. **削除＋-15** を測る。合格 → 2a。不足 → 2b。過補正 → 2c。攻撃区分は合格だが役割・属性・未決着だけ不合格 → **停止して報告**。
2. 2a. **削除＋-10** を測る。合格 → -10 を採用。不合格 → -15 を採用。
   2b. **削除＋-20** を測る。合格 → -20 を採用。不足 → 3 へ。それ以外の不合格 → 停止して報告。
   2c. **削除＋-10** を測る。合格 → -10 を採用。不合格 → 停止して報告。
3. **削除＋-20＋命中-5**（`--cut 20 --acc`）を測る。合格 → 採用。不合格 → **停止して報告**（それ以上の調整はしない）。

試合数は最少 6,000、再計測が全て入っても最大 18,000。
停止したときは `git checkout -- Data/ Tools/aoe_power_rules.py` で前提に戻し、全候補の結果を §31 に記録して報告する（採用案なし。Artifact の再生成と C# の変更も戻す）。

### 4-5. 採用後

採用案を適用した状態（`ADOPTED` も採用案）を最終状態とする。§31 の前後比較表は**採用案の 3,000 試合**（再計測したら1回目・2回目・合算の3列）で作り、基準は §30-6 の 10,000 試合。追加の試合は不要。

## 5. 判断が必要だった点（採った解釈と理由）

### 5-1. 数えない3件

| id | 名前 | 理由 |
|---|---|---|
| `megaton_self_destruct` | メガデストラクト（無・特殊・周囲・威力180） | 専用技（053 だけが持ち、使用者は確定で倒れる）。`verify_attack_moves.py` の `FIXED` が威力180を固定し、learnset 規則でも `SIGNATURE` として各上限の外に置かれている。数えると無の枠を1つ使い、削除の対象（威力順で必ず残る）にもならず、引き下げると錠前に反する |

| `MV_170` | ディスチャージパンチ（電・物理・部屋・威力60） | 物理の範囲技はユーザー指示で対象外 |

3件とも削除も引き下げもしない。ただし §3-4 の評価威力（加算）は射程で決まるので3件にもかかる（`MV_170` は評価威力85。メガデストラクトと `rs_` は learnset の威力規則の外なので結果に影響しない。試算で違反なし）。

### 5-2. 削除数（15個ちょうど）と削る技の決め方

ユーザーの決定「上限より削除数を優先」を受け、**ちょうど15個**削除する（±の幅を許すと、どこで止めるかが恣意的になるため）。属性間の偏りが最小になるよう、次の手順で1つずつ削る:

1. 各属性の残り（数える対象53件）を `(−威力, id)` 順に並べる（同威力は id の文字コード昇順で前を残す）。
2. 毎回、**残数が最も多い属性**の、まだ保護されていない最も威力の低い技を削る候補にする。残数が同じ属性が複数あれば、候補の威力が低い方、さらに同じなら属性順（無・炎・水・草・電・地・氷・竜・闇・虚）で先の方。
3. **闇と虚は対で削る**（闇の技 X を削るときは虚の `void_X` も削る。2個と数える）。虚は闇の複製で、回帰スイートが「虚の攻撃技は元の闇技と一致」を検査しているため。虚は単独では候補にしない。対で削ると15を超えるときは、その候補を飛ばして次の候補へ。
4. 削ると learnset の本数規則（#5 多数側55%・#14 無属性攻撃技2種以上・#15 特性適応技6種以上・#18 多数側の分類＝攻撃区分・虚の個体に虚技・攻撃技0の個体が出ない）を1つでも割る技は**保護**して削らず、次の候補へ（規則を緩めないため）。
5. 1つの属性に最低1個は残す（上限「1〜3個」の下限）。

結果（付録A-1）: 削除15件、残38件。**残数は最大4（8属性）、草・電は3**。保護したのは無の クリティカルエイム（`MV_160`）と ベアスマッシュ（`mvn_004`）（削ると #14 を 005・035／007・072 などが割る）。
削る技は全て各属性の低威力側（威力20〜70）。

参考（同じ手順で上限だけ変えた場合）:

| 案 | 削除数 | 残数の最大 | 約15個とのずれ |
|---|---|---|---|
| 上限3を厳密に（保護なし） | 23 | 3 | +8（#14 を13種・#15 を1種が割る） |
| 上限3を厳密に（保護あり） | 21 | 4（無・氷） | +6 |
| 上限4 | 13 | 4 | -2 |
| **採用: ちょうど15（残数の多い属性から）** | **15** | **4** | **0** |

### 5-3. 「威力グリッドから超過する分は削除」の解釈

「属性ごとの上限（目安3）を超えて範囲技が並んでいる分を、技のプール（＝威力グリッドを埋める技の集合）から取り除く」と読んだ。他の読み方は採らない:

- 「15〜120 の外の威力の技を消す」: 範囲技で 120 を超えるのは高威力の5件（130・135・125×2・130）で、「威力が高い技から残す」と逆になる。
- 「同威力2種の定員を超える分を消す」: 前提コミットで定員超過は0件。引き下げで起きる衝突は、初版と同じく削減量を ±5 ずらす表（`CUT_TABLE`）で避けている（§5-4）。

### 5-4. 引き下げの表（`CUT_TABLE`）

- 公称は案ごとに -10／-15／-20。基準威力35以下（残る4件: 25・30・25・25）は全案 -10（-15/-20 だと威力 10/5 以下になる）。
- 公称どおりだと規則に触れる技だけ削減量を 10〜20 の範囲で ±5 ずらした（付録A-2 の ※）。満たす制約は、
  (a) 同属性・同分類で同威力2種まで（実際の威力、`rs_` 除く）、(b) §B 部屋技の同属性内の間隔10以上（実際の威力、`MV_170` 60 を含む）、
  (c) §3-4 の learnset 規則（評価威力）、(d) 虚 = 闇。ずれの件数は -10 案 9件・-15 案 3件（虚の対を含めると4件）・-20 案 4件。
- -10 案は (c) を満たすために9件を -15/-20 にしており、実質は「-10〜-20 の混在」になる（§31 に注記）。
- 命中-5 は -20 でも「不足」のときだけ、残る38件のうち基準威力80以上の24件（初版と同じ考え方: 威力の点の削減は高威力ほど相対的に軽い）。
  基準威力80未満の部屋技（例: エナジーブラスト・スパインヴァイン）が命中100のまま残るので、回帰の「Room 技で命中100以上」を拾う項目は壊れない。

### 5-5. 新しい評価でどの引き下げ幅でも規則を満たせない learnset 9行

部屋の技は評価威力が `基準威力 − 削減 + 25` で、最大の削減20でも基準より +5 高くなる。前提の learnset は旧い評価（実際の威力）で比をほぼ上限ちょうどに詰めて作られているため、
次の9行は**どの案・どの割り当てでも** #5（少数側の上限）または #13（他属性の威力上限）を割る（付録A-3）。

扱い: **この9行を learnset から除く**（規則を緩めない。新しい評価の定義の下で、その種の learnset に入れてはいけない技になったため。前例: §30-4 で規則に合わない114行を削除した）。
除いても本数規則（#5 55%・#9〜#12・#14・#15・#18）は全て満たす（試算済み）。NPC 構築はこの9行を使っていない。代わりの技は足さない。

### 5-7. learnset 規則の評価の変更（緩和ではなく定義の変更）
