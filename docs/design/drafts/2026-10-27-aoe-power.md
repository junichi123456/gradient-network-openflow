## 0. ユーザー要求と確認結果

原文:

```
範囲技の威力を-10〜-20します。また、場合により命中を-5することも許容します
```

確認の結果（確定）:

1. 威力は**点で引く**（威力そのものから 10〜20 を引く。割合ではない）。命中 -5 も点（命中 100 → 95）。
2. **範囲技 = 射程が 部屋 `Room`・範囲 `Area`・周囲 `Surrounding` の攻撃技**。直線 `Line`・2マス `TwoTile`・全体 `FullFloor` は含めない。

   最終の採用案だけ、その 3,000 試合で §31 の前後比較表を作る（比較の基準は直近 10,000 試合 = `docs/design/pvp_spec.md` §30-6 の値）。

## 2. 現状（実装者向けの要約）

### 2-1. 分析で分かったこと（§30-6 の 10,000 試合と、その追加分析）

完全ランダム構築 10,000 試合を、突破値・気質の自動配分あり／なしの2回測った。攻撃区分別の勝率（BST6 差ロジスティックで補正した「補正後pt」）:

| 攻撃区分 | 配分あり（§30-6） | 配分なし |
|---|---|---|
| 物理攻撃 | -3.4 | -3.3 |
| 特殊攻撃 | **+5.1** | +4.7 |
| 両刀攻撃 | -2.8 | -1.5 |

突破値・気質の寄与は約 0.4pt で、原因ではない。個体ごとの勝率残差を技の性質で回帰すると、攻撃区分だけのモデル（R² 0.350、物理 -1.8／特殊 +6.2、差 8.0pt）に対し、
技の性質（隣接以外の割合・接触率・範囲率）を加えたモデル（R² 0.454）では物理 +3.2／特殊 +2.7（差 0.5pt）に縮む。効いていたのは
**範囲率（その個体の攻撃技のうち射程が Room/Area/Surrounding のものの割合）で、100%あたり +30pt**。特殊攻撃の個体の範囲率は約19%、物理攻撃は約2%。
属性別の補正後差は -3.1〜+2.1pt（炎 +2.1、無 -3.1）に収まっている。

範囲技は1回の行動で複数の相手（4対4）に当たるのに、威力が単体技と同等。特殊技の平均威力（本書の集計、前提コミット）:

| 射程 | 件数 | 平均威力 |
|---|---|---|
| 単体 Adjacent | 127 | 73.9 |
| 範囲 Area | 21 | 74.3 |
| 部屋 Room | 33 | 69.2 |
| 直線 Line | 61 | 53.7 |

物理技はほぼ全て単体（316/349）で、範囲技は Room の1技（ディスチャージパンチ）だけ。

かつて `Tools/rebalance_attack_moves.py` §4 が「射程を威力で払う」（Area -15・Room -20）処理を特殊技に一度かけたが、その後の威力グリッドの充填などで均され、
現在の範囲技は割り引かれていない。**このツールを含む過去の一括処理ツール（`rebalance_attack_moves.py`・`cap_moves_by_range.py`・`prune_attack_moves.py`・
`add_void_type.py`・`generate_learnset.py`・`generate_npc_teams.py` など）は再実行しない**（威力や learnset が作り直されて本書の変更が壊れる。
`add_void_type.py` は闇技を虚へ複製し learnset を威力の近さで付け替える）。

### 2-2. 射程の挙動（`Scripts/Turn/TargetResolver.cs`）

- `Room`: 盤面（部屋）全体の**相手側だけ**に当たる（味方は巻き込まない）。対戦盤は1部屋なので実質「相手全員」。
- `Area`: 狙ったマスを中心に 3×3。**味方も巻き込む**。
- `Surrounding`: 使用者中心の 3×3。該当するのは専用技メガデストラクト1件のみ。
- NPC（`Scripts/Battle/NpcOpponent.cs`）は変化技を評価せず、攻撃技を威力・命中・当たる数から評価して選ぶ。威力を下げれば範囲技が選ばれる頻度と与ダメージが下がる。

## 3. 変更内容

### 3-1. 新規 `Tools/aoe_power_rules.py`（範囲技の表と割り当ての唯一の実体）

生成（apply）と検証（verify 2本）が同じ表を見るため、表はこのモジュールだけに置く。中身:

1. `AOE_RANGES = ('Room', 'Area', 'Surrounding')`
2. `AOE_EXCLUDED = {'megaton_self_destruct': '専用技', 'rs_scorch_smog': '制限技', 'MV_170': '物理の唯一の範囲技'}`（理由は §5-1。値は短い理由文字列でよい）
3. `AOE_BASE = {move_id: (基準威力, 基準命中), ...}` — **前提コミットの moves.json の値を直書きした53件**（付録A の「威力」「命中」列）。
   実装者は一度だけ HEAD の moves.json から生成して貼り付け、付録A と一致することを確かめる（不一致なら報告）。以後この表が「基準威力」の唯一の出典。
4. `ADOPTED = (0, False)` — 現在適用中の案 `(削減幅D, 命中-5併用か)`。`D ∈ {0, 10, 15, 20}`。`D=0` は「変更なし（基準のまま）」。apply ツールがこの1行を書き換える。
5. `def base_power(m)` — 対象技なら `AOE_BASE[id][0]`、それ以外は `m['power']`。
6. `def solve(D)` — 下の決定的アルゴリズムで `{move_id: 削減量}` を返す（53件）。`D=0` なら全件 0。
7. `def acc_cut(move_id, acc)` — `acc` が真で基準威力 ≥ 80 なら 5、他は 0。

**`solve(D)` のアルゴリズム（付録A の値はこれで再現できる。実装後に付録A と突き合わせること）**

- 公称削減量 `nominal(p) = 10 if p <= 35 else D`（p は基準威力）。基準威力35以下の低威力技は、どの案でも -10 を公称とする（-15/-20 だと威力 5/0 になり攻撃技でなくなるため）。
- 各技の選択肢: `d ∈ {10, 15, 20}` のうち `p - d >= 10` を満たすもの。
- 属性ごとに独立に解く。**虚(Void) は解かず、`void_X` の削減量 = `X`（闇の元技）の削減量**（回帰スイートが「虚の攻撃技57件が元の闇技と威力・命中・射程・PP・接触で一致」を検査しているため）。
- 属性 el の対象技を `(-基準威力, id)` 順に並べ、選択肢の直積を全探索（最大 3^6 = 729 通り）し、制約を満たす中で次の辞書式最小を採る:
  `(Σ|d - nominal|, d ≠ nominal の件数, (-d_1, -d_2, ...))`（同点なら並び順の前の技ほど大きく削る）。
- 制約（いずれも**変更後の実際の威力**で見る。`verify_attack_moves.py` の既存規則と同じ定義）:
  - (a) 同威力2種まで: 属性 el・分類ごとに、「対象外で `rs_` でない攻撃技（威力>0）の実効威力（連続技は最大回数倍。`verify_attack_moves.py` の `eff`）」と「対象技の変更後威力」を合わせて、同じ値が3件以上にならない。
  - (b) §B 部屋技の間隔: 属性 el の Room 射程の攻撃技（分類をまたぎ、対象外も含む。電の MV_170 威力60 を含む）の威力を昇順に並べ、隣どうしの差が全て10以上。
- 解が無い属性があれば例外を投げる（前提コミットのデータでは D=10/15/20 の全てで解がある。付録A の ※ が公称からずれた技）。

### 4-2. 採用基準

| 指標 | 基準 |
|---|---|
| 攻撃区分3（物理攻撃・特殊攻撃・両刀攻撃）の補正後pt | 全て **±3pt 以内** |
| 役割9（攻撃区分/耐久区分）の補正後pt | 全て ±5pt 以内 |
| 属性10の補正後pt | 全て ±5pt 以内 |
| 未決着率（U / 試合数） | 2% 以下 |

耐久区分・俊敏帯は参考（合否に使わない）。

### 4-3. 3,000 試合の標準誤差（試算）と境界の扱い

3,000 試合の出場数は §30-6（10,000 試合）の約 0.3 倍: 物理攻撃 ≈11,600、特殊攻撃 ≈9,200、両刀攻撃 ≈2,900、役割 ≈800〜4,300、属性 ≈2,000〜4,000。
勝率の標準誤差を `0.5/√n` に、同じ側に同じ区分が複数いる相関の補正（設計効果 ≈1.5、√≈1.22）を掛けて見積もると:

| 区分 | 出場数（3,000試合） | SE（試算） |
|---|---|---|
| 物理攻撃 | ≈11,600 | ≈0.6pt |
| 特殊攻撃 | ≈9,200 | ≈0.65pt |
| 両刀攻撃 | ≈2,900 | ≈1.1pt |
| 役割9 | ≈800〜4,300 | ≈0.9〜2.2pt（両刀攻撃の3つが最大） |
| 属性10 | ≈2,000〜4,000 | ≈1.0〜1.4pt |

同じ案の計測をやり直したときの差の SE は上の √2 倍（攻撃区分で ≈0.9〜1.5pt）。ゆえに ±3pt の判定は1回の 3,000 試合では境界付近で揺れる。判定には `--bootstrap 200` の実測 SE を使う:

- 各行について、`| |補正後pt| − 基準 | < SE` なら、その行は**境界**。
- 4-2 の全行が境界でなく基準内 → その候補は **合格**。境界でない行が1つでも基準外 → **不合格**。
- 境界の行が1つでもあり、他に基準外の行が無い → **同じ案を同条件でもう 3,000 試合**測り、**計 6,000 試合を合算した点推定**で合否を決める（合算後は境界判定をせず、点推定が基準内なら合格。再計測は1候補につき1回まで）。
- 2案が合格したら、**変更幅の小さい方**を採る（-10 < -15 < -20 < -20+命中-5）。

### 4-4. 逐次の手順（総試合数を最小にする）

攻撃区分の不合格を向きで2つに分ける（判定は 4-3 の合否と同じ値＝1回目、または再計測後の合算で行う）:

- 「不足」= 前提と同じ向きに偏りが残っている: 特殊攻撃 > +3、または 物理攻撃・両刀攻撃のいずれかが < -3（かつ「過補正」の条件に当たらない）。
- 「過補正」= 逆向きに超えた: 特殊攻撃 < -3、または 物理攻撃・両刀攻撃のいずれかが > +3（かつ「不足」の条件に当たらない）。
- 両方に当たる場合は分岐に当てはまらないので停止して報告。

1. **-15** を測る。
   - 合格 → 2a へ。
   - 不合格で「不足」→ 2b へ。
   - 不合格で「過補正」→ 2c へ。
   - 攻撃区分3は合格だが役割・属性・未決着だけが不合格 → **停止して報告**（範囲技の威力では直す筋が無いので、それ以上いじらない）。
2. 
   - 2a. **-10** を測る。合格 → **-10 を採用**。不合格 → **-15 を採用**。
   - 2b. **-20** を測る。合格 → **-20 を採用**。「不足」で不合格 → 3 へ。それ以外の不合格（過補正、または攻撃区分以外の不合格）→ 停止して報告。
   - 2c. **-10** を測る。合格 → **-10 を採用**。不合格 → 停止して報告。
3. **-20 + 命中-5**（`--cut 20 --acc`）を測る。合格 → 採用。不合格 → **停止して報告**（それ以上の削減・別の調整はしない）。

試合数: 最少 6,000（-15 と -10、または -15 と -20）、再計測が全て入った最大でも 18,000。
「停止して報告」のとき、moves.json は**最後に測った案のまま残さず `--cut 0` で戻し**、全候補の計測結果を §31 に記録して報告する（採用案なし）。

### 4-5. 採用後

採用案で `apply_aoe_power_cut.py` を実行した状態（`ADOPTED` も採用案）を最終状態とする。§31 の前後比較表は**採用案の 3,000 試合**（再計測した場合は1回目・2回目・合算の3列）で作り、比較の基準は §30-6 の 10,000 試合の値。
採用案のための追加の試合は不要（候補の計測は最終と同じ moves.json で行っている）。

### 5-2. 威力の引き方（10〜20 のどこを使うか）

- 案は「公称の削減幅 D ∈ {10, 15, 20}」の一律。ただし基準威力35以下の14件は全案で -10（-15/-20 だと威力 5/0 になり、威力0は変化技扱いで NPC が使わず `§4 威力>0` にも反する）。
- 公称どおりだと既存規則（同威力2種まで・§B 部屋技の間隔10）に触れる技が出るので、**その技だけ削減量を 10〜20 の範囲内で ±5 ずらす**（§3-1 の `solve`）。ずれは各案で2〜4件（付録A の ※）。ユーザー指示の「-10〜-20」の範囲は全件で守られる。
- 命中-5 は、-20 でも「不足」のときだけ使う。対象は**基準威力80以上の24件**に限る。理由: 削減20は威力130の技で約15%、威力45の技で約44%と、高威力ほど相対的に軽い。命中で高威力帯を追加で割り引けば相対の負担がそろう。
  また、低威力の Room 技を命中100のまま残すので、回帰スイートの「Room 技で命中100以上」を拾う項目（§6-3）が壊れない。
- 段階を威力帯でさらに細かく分ける案（例: 低威力-10・高威力-20 の混在）は、候補の数が増えて 3,000 試合の逐次計測で判定できないので採らない。

### 5-3. 既存の検証・規則との整合（実データで調べた結果）

付録A の3案それぞれを適用したデータで3本の検証を走らせた結果（`solve` の割り当て込み）:

| 規則 | 影響 | 扱い |
|---|---|---|
| 同属性・同分類で同威力2種まで | 一律に引くと 2〜4 件違反（電・物理 50/45/40、草・特殊 15、闇/虚・特殊 70） | `solve` の割り当てで回避。**緩めない**。MV_170 は除外（§5-1） |
| §B 部屋技は同属性内で威力差10以上 | 一律だと電（60 の MV_170 と特殊の部屋技）で衝突し得る | `solve` の制約に入れて回避。**緩めない** |
| 威力グリッド（15..120 の5刻みが各属性・各分類に最低1技） | **どの案でも 32〜38 か所が空く**。範囲技が単独で埋めていた点が41か所あり（例: 闇・特殊の 20/25/55/85/105 は全て範囲技だけ）、範囲技どうしの付け替えでは埋まらない（闇・特殊 105 より上に範囲技が無い等） | **基準威力で数える**（緩和）。理由: グリッドは「どの威力段階の技も learnset の素材として存在する」ことの保証で、learnset はその段階で既に作られており本書では作り直さない。範囲技の削減は射程の値段（旧 §4 の「射程を威力で払う」と同じ考え方）であって段階の欠落ではない。代替検査: 新項目で対象53件の威力が `基準威力 − solve(D)` に一致することを固定し、基準威力の表 `AOE_BASE` を唯一の出典にする |
| learnset #5 少数側 ≤ 多数側最高威力×0.6（両刀0.9） | **どの案でも 59〜62 種が違反**。全件、多数側の最高威力の技が対象の範囲技（例: 多数側 125 の範囲技が 115 に下がり、少数側 75 > 69）。learnset の生成がこの比をほぼ上限ちょうどに詰めているため、-10 でも違反する。learnset・他の技は変えられない（本書の範囲外） | **基準威力で比べる**（緩和）。理由: この規則は「少数側の技が主力を食わない＝攻撃区分の性格を保つ」ためのもので、範囲技は複数に当たるぶん同威力の単体技より実効値が高い。基準威力（単体換算）で比べるのが規則の趣旨に合う。比率 0.6/0.9 は変えない。代替検査は上と同じ（基準威力の表と割り当ての固定） |
| learnset #2・#3・#13（威力の上限・本数） | 威力が下がるだけなので悪化しない（試算で全案 PASS） | 変えない |
| NPC 構築（`verify_npc_teams.py`） | 威力>0 しか見ない。対象技は最低でも威力10 | 変えない（全案 PASS） |
| 制限技 `RS_SPEC`・メガデストラクト `FIXED` | 対象外なので不変 | 変えない |
| 虚と闇の性能一致（回帰スイート） | 虚は闇の削減量を写すので一致を保つ | — |
| 到達性 `BANDS`（`build_ls_payload.py`） | 表示のみ。帯の件数が動き、威力10になる5件は帯（15〜）の外 | 変えない（§31 に前後を載せる） |
