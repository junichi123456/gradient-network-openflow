# 対戦（PvP）仕様 — 設計メモ

レベル50固定・6匹登録／4匹選出の対人戦を実装するための仕様と、現行コードとの
差分をまとめたもの。**技リストと learnset は完成済みとみなし、ここでは触らない。**

---

## 1. 確定仕様

### 前提

- learnset 内の技は**レベルキャップに関係なく変更可能**（対戦では習得レベルを見ない）
- 対戦時はすべてのパルが**レベル50**に調整される

### 対戦の流れ

| # | フェーズ | 内容 |
|---|---|---|
| 1 | パーティ登録 | 6匹。**同一種族不可**。持ち物は1匹1つ、**重複不可** |
| 2 | 対戦受付 | 待機 |
| 3 | 相手party開示 | **種族のみ**開示。技・持ち物は非開示 |
| 4 | 選出 | 6匹から4匹。**制限時間50秒**。両者完了か時間切れで次へ。時間切れ時は登録順の昇順で自動選出 |
| 5 | 配置 | 縦2×横3（自陣6マス）。相手と合わせて4×3。**上列が相手と対面** |
| 6 | 対戦 | **20分**。片方が全滅で生存側の勝ち。時間切れで両者生存なら引き分け |

### 対戦中の進行

- **ターン** = パル1匹の行動。**サイクル（一巡）** = 全員が1回行動した単位
- 1ターンにつき、両陣営が1匹ずつ指定して行動を決定 → その後、行動順に従って処理
- 4匹選出なので **1サイクル = 4ターン = 8回の行動**
- 1サイクル中、各パルは**1ターンだけ**行動する。1ターン目に動いたパルは
  2〜4ターン目は行動できない。4ターン目に動けばそこでサイクル完了なので、
  2サイクル目（=5ターン目）から再び行動できる
- **味方は全て自分で操作する。自動処理による行動は行わない**

### 行動順の決定

1. **優先度**が高いパルが、合計種族値にかかわらず先に行動する
2. 優先度が同じなら、**合計種族値（BST）が低いほうが先**
3. BST も同じならランダム

## 2. 本メモで決定した4点

| 論点 | 決定 |
|---|---|
| 射程の再定義 | **盤面全体を1つの部屋とみなす**（Room = 味方を除く敵4匹全体） |
| 対戦中の移動 | **移動も1ターンの行動として選べる**（迷宮と同じ） |
| 行動順の比較単位 | **そのターンに指定された2匹**の BST を比較 |
| 優先度の所在 | **一部の技・特性・持ち物**に配布する |

BST 同値によるランダム決着は稀に留まる。任意の2種で BST が一致する確率は
**2.6%**（41,041組中1,072組、45段階に分散）なので、例外処理として妥当な頻度。

## 3. 射程再定義の帰結

盤面が 4行×3列（12マス）と狭いため、迷宮向けに設計した射程の力関係が
そのまま持ち込むと崩れる。**Room を全体攻撃とみなす決定の副作用が
Room 以外にも及ぶ**点に注意。

### 3-1. Area(19技) が Room より広く、しかも味方を巻き込む

Area は「着弾点中心の3×3」。**幅3の盤面では3×3が必ず全幅を覆う**ため、
実効範囲は 3行×3列 = **12マス中9マス**になる。一方 Room は味方を除外する
（`TargetResolver` の既存仕様）が、**Area は味方に当たる**。

結果として「Area のほうが Room より広く当たるのに、自分の味方も巻き込む」
という逆転が起きる。Area の3×3を盤面用に縮める（例: 十字5マス）か、
Area にも味方除外を入れるかの判断が要る。

### 3-2. Line(54技) が TwoTile(27技) の下位互換になる

Line は非貫通（最初に当たった1体のみ）。奥行きが4しかないので、
**前列から撃つと届く敵マスは2つだけ**で、TwoTile と実効射程が並ぶ。
にもかかわらず射程課金は Line が -10、TwoTile が -5 で、威力に差がついている。

| 射程 | 技数 | 威力中央値 | 味方が射線にいた場合 |
|---|---|---|---|
| Line | 54 | **50** | **不発**（味方が射線を塞ぐ） |
| TwoTile | 27 | **80** | 素通りして奥の敵に当たる |

威力で30も負けたうえ、味方処理でも不利。**Line 技54種が対戦でほぼ死に技になる。**
後列から撃てば3マス先まで届くという利点は残るが、非貫通なので手前の敵に
吸われる。Line の射程課金を見直すか、対戦盤では貫通させるかの判断が要る。

### 3-3. Surrounding（メガデストラクト）が自陣を巻き込む

自身中心の3×3で味方も対象。自陣が3マス幅なので、**確殺反動と引き換えに
自分の残り3匹も巻き込みうる**。威力180の全体技として機能するのか、
自爆ゆえの自傷リスクとして許容するのかを決める必要がある。

### 3-4. 設置技7種は盤面の広さ前提

`HalfArea`（部屋の半分）4種、`FourEmptyTiles` 2種、`ClearRadiusFour` 1種。
盤面が12マスなので HalfArea = 6マス = **自陣または敵陣まるごと**に相当する。

### 3-5. 参考: 射程ごとの現状

| 射程 | 技数 | 威力レンジ | 平均 |
|---|---|---|---|
| Adjacent | 393 | 15〜135 | 68 |
| Line | 54 | 15〜135 | 54 |
| Room | 31 | 20〜130 | 70 |
| TwoTile | 27 | 35〜120 | 81 |
| Area | 18 | 25〜135 | 77 |
| Surrounding | 1 | 180 | 180 |

FullFloor 射程の技は0件。Room 技の最高威力は **ビー・クワイエット（草・特殊・威力130・命中100）**。

## 4. 現行コードとの差分

### そのまま使えるもの

- `DamageCalculator` / `DamageContext` — 特性・天候・状態異常・ランク補正のフックが揃っている
- HAD式は任意レベルで動く。**レベル50固定は `Level = 50` を入れるだけ**。
  既存のバランス基準値がもともとLv50基準（同種ミラーが約10発で決着）
- `StatusEffectManager` / `TypeChartManager` / `TraitDatabase` / `MoveDatabase` / `MoveManager`(PP)
- グリッドと `TargetResolver` の射程ジオメトリ（射程の解釈だけ差し替える）

### 作り直しが必要なもの

| # | 項目 | 現状 |
|---|---|---|
| 1 | **行動順モデル** | エネルギー蓄積式。`Entity.Speed` は固定100で種族値と無関係。素早さ200なら1巡2回動くモデルで、「1巡に全員1回」と両立しない。対戦用スケジューラを別に立てる |
| 2 | **優先度フィールド** | 582技すべてに項目なし。`moves.json` にスキーマ追加が必要 |
| 3 | **持ち物** | `items.json` は6件（消耗品2・投擲1・素材3）。**持ち込み装備品は0件**。アイテム群の新規設計が必要 |
| 4 | **パーティ上限** | `PartyManager.MaxActiveParty = 2`。6匹登録→4匹選出は別モデル |
| 5 | 選出・配置・時間制限・通信対戦 | 未実装 |

## 5. 未決事項

### 5-1. 「ターン」の定義変更にともなう持続時間の再解釈

対戦では1ターン = パル1匹の行動なので、**既存の「Nターン」がすべて意味を変える**。

- 天候技6種はいずれも **20ターン** 継続 → 対戦では **5サイクル**分
- 状態異常の持続、ランク減衰も同様に読み直しが必要

サイクル単位に換算するのか、ターン単位のまま据え置くのかを決める。

### 5-2. 行動決定の同時性

「1匹ずつお互いに指定し、行動を決定する」とあるが、**相手がどのパルを指定したかを
見てから自分の行動を決められるのか**（逐次公開）、それとも同時に伏せて決めるのか
が未定。ここは読み合いの質を大きく左右する。

### 5-3. 4匹を6マスにどう置くか

自陣は2×3 = 6マスあり、選出は4匹。6マスから自由に4マス選ぶのか、
前列3・後列1のような定型に縛るのかが未定。

### 5-4. 優先度の値域と配布量

技・特性・持ち物の3か所に配る方針は決まったが、値域（-1〜+2 など）と
何技に配るかは未設計。**先制技を配りすぎると BST による行動順が形骸化する**ため、
learnset の共有率と同じく配布量の上限を決めるのが安全。

### 5-5. 交代の有無

選出した4匹が全員盤面に出る形なので、**控えがいない**。したがって交代の概念は
発生しない、という理解でよいか。

## 6. 実装の順序（案）

作る量が多いので、対戦が成立する最小構成から積む。

1. **対戦用スケジューラ** — サイクル/ターン、BST比較、優先度フック（値は全0でよい）
2. **射程の対戦用解釈** — Room=敵全体、Area/Line/Surrounding の扱いを §3 の判断に従って差し替え
3. **Lv50固定とパーティ6/選出4** — `PartyManager` の拡張、同一種族禁止
4. **配置フェーズ** — 4×3盤面、移動を行動として実装
5. **優先度フィールド** — `moves.json` スキーマ追加と配布
6. **持ち物** — 装備品の設計と重複禁止
7. **時間制限・勝敗判定** — 50秒/20分、全滅判定
8. **通信対戦** — 最後
