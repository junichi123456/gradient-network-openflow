# 対戦（PvP）仕様 — 設計メモ

レベル50固定・6匹登録／4匹選出の対人戦を実装するための仕様と、現行コードとの
差分をまとめたもの。**技リストと learnset は完成済みとみなし、ここでは触らない。**

---

## 1. 確定仕様

### 前提

- learnset 内の技は**レベルキャップに関係なく変更可能**（対戦では習得レベルを見ない）
- 対戦時はすべてのパルが**レベル50**に調整される

### 対戦の流れ

| # | フェーズ | 内容 |
|---|---|---|
| 1 | パーティ登録（構築） | 6匹。**同一種族不可**。持ち物は1匹1つ、**重複不可**。**技4つもここで確定する** |
| 2 | 対戦受付 | 待機 |
| 3 | 相手party開示 | **種族のみ**開示。技・持ち物は非開示 |
| 4 | 選出 | 6匹から4匹。**制限時間50秒**。両者完了か時間切れで次へ。時間切れ時は登録順の昇順で自動選出。**技と持ち物は構築段階で確定済みなので、ここでは触らない** |
| 5 | 配置 | 自陣は縦2×横3の6マス。そこへ4匹を**自由配置**。**上列が相手と対面** |
| 6 | 対戦 | **20分**。片方が全滅で生存側の勝ち。時間切れで両者生存なら引き分け |

### 盤面

- **8行（縦）×7列（横） = 56マス**。自陣・敵陣の2×3ブロックを**中央に配置**する
- 選出した4匹は**全員が盤面に出る**。控えがいないので**交代は発生しない**
- 座標は**論理座標を1つだけ**持つ。論理座標では常に自陣が下（Yが大）、
  敵陣が上（Yが小）。**描画側が自分の陣営を下に見せるため、相手視点では
  盤面を180度回転して描く。**ロジックは1つの向きしか知らない
  （`BattleBoard.ToViewOf`）

### 対戦中の進行

- **ターン** = パル1匹の行動。**サイクル（一巡）** = 全員が1回行動した単位
- 1ターンにつき、両陣営が1匹ずつ指定して行動を決定 → その後、行動順に従って処理
- **指定するパルと行動はどちらも伏せて同時に決める**
- 4匹選出なので **1サイクル = 4ターン = 8回の行動**
- 1サイクル中、各パルは**1ターンだけ**行動する。1ターン目に動いたパルは
  2〜4ターン目は行動できない。4ターン目に動けばそこでサイクル完了なので、
  2サイクル目（=5ターン目）から再び行動できる
- **味方は全て自分で操作する。自動処理による行動は行わない**
- **移動も1ターンの行動として選べる**（迷宮と同じ）

### 行動順の決定

1. **優先度**が高いパルが、合計種族値にかかわらず先に行動する
2. 優先度が同じなら、**そのターンに指定された2匹**のうち合計種族値（BST）が低いほうが先
3. BST も同じならランダム

**優先度を持つ技はヘッドバット（無・物理・威力40・Adjacent）の +1 のみ。**
他は技・特性・持ち物に今後配布する。

### 持続時間の扱い

| 対象 | 単位 |
|---|---|
| 天候（6技すべて20ターン） | **ターン**のまま。1サイクル=4ターンなので **5サイクル**分 |
| 状態異常 | **サイクル** |
| ランク減衰 | **サイクル** |

## 2. 射程は改造不要で成立する

当初は対戦盤用に射程を解釈し直す作業を見込んでいたが、**アリーナを
「全マスが単一の部屋」として生成すれば、既存コードのまま意図どおり動く。**

`TargetResolver` の Room は `FloorController.GetRoomBoundsAt()` を引く。
迷宮では廊下（RoomId < 0）で null が返り単体攻撃にフォールバックするが、
**8×7の全タイルに同一の RoomId を振れば盤面全体が1つの部屋になり、
Room = 味方を除く敵4匹**が自然に成立する。決定どおりの挙動になる。

同時に、他の射程も 56マスの盤面では迷宮と同じ感覚で機能する。

| 射程 | 技数 | 8×7盤面での挙動 |
|---|---|---|
| Adjacent | 393 | 隣接1体。移動と組み合わせて機能する |
| Line | 54 | 最大7マス先まで。非貫通で最初の1体 |
| Room | 31 | 盤面全体 = 敵4匹（味方は対象外） |
| TwoTile | 27 | 2マス先まで。味方は素通り |
| Area | 18 | 3×3 = 56マス中9マス（16%）。味方も巻き込む |
| Surrounding | 1 | 自身中心3×3。**味方も巻き込む（仕様どおり）** |

設置技7種も改造不要。`AttackAction.HalfAreaTiles` は **12マス固定**で
部屋の広さに依存しないため、56マスの盤面では21%を占める。

**Line についての前回の指摘は取り下げる。** 4行盤面を前提に「TwoTile の
下位互換」と書いたが、8行なら射程差が効く。威力90以上の Line 技は9種あり
**すべて特殊技**で、特殊型の主力として機能する。

| 技 | 属性 | 威力 | 命中 |
|---|---|---|---|
| ダイヤモンドダスト | 氷 | 135 | 100 |
| ドラゴンヴェインバースト | 竜 | 130 | 65 |
| レールガン | 電 | 115 | 65 |
| オーロラカノン | 無 | 110 | 100 |
| アースクエイク | 地 | 110 | 100 |

Room と Area の威力バランスは**アイテム側で調整する**方針。

## 3. 現行コードとの差分

### そのまま使えるもの

- `DamageCalculator` / `DamageContext` — 特性・天候・状態異常・ランク補正のフックが揃っている
- HAD式は任意レベルで動く。**レベル50固定は `Level = 50` を入れるだけ**。
  既存のバランス基準値がもともとLv50基準（同種ミラーが約10発で決着）
- `TargetResolver` の射程ジオメトリ（**§2 のとおり無改造**）
- `StatusEffectManager` / `TypeChartManager` / `TraitDatabase` / `MoveDatabase` / `MoveManager`(PP)
- `FloorController` の天候・フィールド・トラップ機構

### 作り直しが必要なもの

| # | 項目 | 現状 |
|---|---|---|
| 1 | **行動順モデル** | エネルギー蓄積式。`Entity.Speed` は固定100で種族値と無関係。素早さ200なら1巡2回動くモデルで、「1巡に全員1回」と両立しない。対戦用スケジューラを別に立てる |
| 2 | **状態異常/ランクの刻み** | 現在は行動ごと（`ResolveStatusTick`）。**サイクル境界へ移す** |
| 3 | **優先度フィールド** | 582技すべてに項目なし。`moves.json` にスキーマ追加。値を持つのは当面ヘッドバット1件 |
| 4 | **持ち物** | `items.json` は6件（消耗品2・投擲1・素材3）。**持ち込み装備品は0件**。アイテム群の新規設計が必要 |
| 5 | **パーティ上限** | `PartyManager.MaxActiveParty = 2`。6匹登録→4匹選出は別モデル |
| 6 | 選出・配置・時間制限・通信対戦 | 未実装 |

## 4. 実装の順序

射程作業が消えたぶん、骨格を先に通せる。

### 第1段階: 対戦が成立する最小構成（ヘッドレス検証可能）

1. **アリーナ生成** — 8×7・全マス単一 RoomId の `FloorController`。中央に2×3ブロック2つ
2. **対戦用スケジューラ** — サイクル/ターン、伏せて同時決定、優先度→BST→ランダムの行動順
3. **Lv50固定** と 4v4 の配置
4. **優先度フィールド** — `moves.json` にスキーマ追加、ヘッドバットに +1

ここまでで、両陣営の行動を台本で与えた4v4がヘッドレスで最後まで回る。
射程・ダメージ・特性・状態異常が対戦盤で正しく動くことを機械検証できる。

### 第2段階: ルールの肉付け

5. **サイクル単位の状態異常/ランク減衰**
6. **6匹登録／4匹選出** — 同一種族禁止、時間切れ時の登録順自動選出
7. **配置フェーズ** — 自陣6マスへの自由配置

### 第3段階: 対戦環境

8. **持ち物** — 装備品の設計、重複禁止、優先度への関与
9. **時間制限・勝敗判定** — 選出50秒 / 対戦20分 / 全滅判定
10. **通信対戦**

## 5. 未決事項

### 5-1. 優先度の値域と配布量

現状はヘッドバット +1 のみ。今後 技・特性・持ち物へ配る際、**先制技を配りすぎると
BST による行動順が形骸化する**ため、learnset の共有率と同じく配布量の上限を
決めるのが安全。

### 5-2. 決定済み: 乱数はシード管理しない

命中判定・急所（`GD.Randf()`）、設置技の配置、行動順の同値決着はいずれも
素のランダム。**リプレイや再現検証はユーザー側の負担で行い、ゲーム側では
シード管理を行わない。**

## 6. 構築データモデル

技4つと持ち物は**構築段階（6匹を選定する時点）でユーザーが確定させる**。
選出フェーズは「登録済みの6匹から4匹を選ぶ」だけで、技や持ち物には触らない。
対戦中の変更もできない。

`BattleEntry` が1匹ぶんの登録内容（種族 + 技4つ + 持ち物1つ）、
`BattleTeam` が6匹ぶんをまとめて構築時の制約を機械検証する。

| 検証 | 内容 |
|---|---|
| 登録数 | 6匹ちょうど |
| 同一種族 | 重複不可 |
| 持ち物 | 重複不可（持たせない = null は重複判定の対象外） |
| 技の数 | 1〜4（`MoveManager.MaxMoves = 4`） |
| 技の重複 | 同じ技を2枠には積めない |
| 技の出所 | **その種族の learnset 内であること。習得レベルは問わない** |
| 実在性 | 種族・技・持ち物のIDが実在すること |
| 選出 | 登録した6匹の中からちょうど4匹。重複不可 |

時間切れ時の自動選出は `BattleTeam.AutoSelect()`（登録順の昇順で先頭4匹）。

## 7. 持ち物 16種

構築段階で1匹1つ、チーム内で重複不可。**使い切り9種**（条件を満たすと1回だけ
発動して消費）と**所有中持続7種**。

### 使い切り

| 名前 | 効果 | 接続先 |
|---|---|---|
| ガードトニック | HPが50%未満になると最大HPの25%回復 | 被弾直後の閾値判定 |
| ラストトニック | HPが33%以下になると最大HPの50%回復 | 同上 |
| エンデュアチャーム | HP満タンから即死する攻撃を受けてもHP1で耐える | `TakeDamage` 直前 |
| クリットシェル | 急所を受けた時、そのダメージを90%減 | ダメージ確定後 |
| ウィークシェル | 弱点属性を受けた時、そのダメージを75%減 | ダメージ確定後（相性倍率>1で判定） |
| ルームミラー | **相手の** Room射程を受けた時、受けたダメージを使用者へ反射 | `TakeDamage` 直後 |
| エリアイージス | **相手の** 範囲射程を受けた時、所持者以外の味方はダメージを受けない | AoE対象ループの手前 |
| ランクアンカー | 自分のランクが下がったら、**下がった分だけ**戻す | `ApplyRankTo` |
| キュアベル | 自分が状態異常になったら回復する | `ApplyAilmentTo` |

### 所有中持続

| 名前 | 効果 | 接続先 |
|---|---|---|
| リジェネバンド | 自分のターン終了時、HPを10%回復 | `BattleScheduler` のターン終了 |
| パージバンド | 自分のターン終了時、全状態異常蓄積値が100減少 | 同上 |
| パワーレンズ | 物理技の使用時、攻撃力(実数値)+25% | `AtkMultiplier` |
| フォーカスレンズ | 特殊技の使用時、攻撃力(実数値)+25% | `AtkMultiplier` |
| アイアンプレート | 物理技の被弾時、防御力(実数値)+30% | `DefMultiplier` |
| マインドプレート | 特殊技の被弾時、防御力(実数値)+40% | `DefMultiplier` |
| ワイドウォード | 全体攻撃技(Room/Area)の攻撃を受けない | 既存の無効化と同じ早期return |

### 確定した解釈

- **攻撃/防御の増減はその一撃の計算にだけ乗る**（解釈a）。被弾を機に恒久バフを
  得て累積する形ではない。
- **ルームミラー / エリアイージスは相手が使用した技のみ**に反応する。
- **ランクアンカーは下がった分だけ戻す。**全ランクを0に均すのではない。
- **エリアイージスの「範囲射程」は Area と Surrounding。**Room は元々味方に
  当たらないので対象外。所持者自身は庇わない。

### ワイドウォードの強さは意図的

Room 31技 + Area 18技 = 49技を完全無効にするが、**これは対面対戦へ構築を
寄せるための意図的な設計**。所持者が後方にいる場合、直線射程・2マス射程の
技の有意性が高まるという副次効果も狙っている。
