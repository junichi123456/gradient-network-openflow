# レイドボスMod 構想書（共通基盤 v0.1）

マルチサーバー向けの独自レイドボスModについて、**すべてのボスに共通する前提・数値基準・ルール・実装構造**をまとめる。
個別ボスの攻撃パターンは、この基盤の上にデータとして載せる。

- 対象バージョン想定: Minecraft Java 1.21.x（メイスが存在する版）
- 想定ローダー: NeoForge 1.21.1（推奨・理由は §8）／Fabric でも同等の設計で実装可能
- 用語: tick = 1/20 秒

---

## 1. 前提仕様（ユーザー定義・全ボス共通）

| # | 仕様 |
|---|------|
| P1 | エンチャント無しネザライトの剣で、クールダウン完了ごとにクリティカルを当て続ければ **3分** で討伐できる |
| P2 | 実戦では回避・追従の時間が入るため **約10分** の戦闘を見込む |
| P3 | メイスによるダメージ無効 |
| P4 | 矢・ポーションによるダメージ無効 |
| P5 | トライデントによるダメージ無効 |
| P6 | 状態異常無効 |
| P7 | 戦闘用ワールド（次元）ではプレイヤーはブロックを設置できない |
| P8 | P7 により、ボスは活動時間の大半を **接地** していなければならない（公平性） |

## 2. 数値基準（Damage Budget）

### 2.1 基準DPS

| 項目 | 値 | 根拠 |
|------|----|------|
| ネザライトの剣 攻撃力 | 8 | バニラ値 |
| 攻撃速度 | 1.6 /秒 | バニラ値 |
| クールダウン | 20 / 1.6 = **12.5 tick (0.625秒)** | |
| クリティカル倍率 | ×1.5 → **12 ダメージ/撃** | 落下中・非スプリント・クールダウン90%超が条件 |
| 理論DPS | 12 / 0.625 = **19.2** | |
| 実用DPS（ジャンプ周期≒13 tick に律速） | 約 18.5 | ジャンプ滞空≒12 tick + 着地1 tick |

### 2.2 基準HP

```
HP_base = 19.2 × 180秒 = 3,456   （1人換算・表示上は 3,456 を正とする）
```

> **注意: バニラの `max_health` 属性は上限 1024。** 3,456 以上を素直に設定できないため、
> ボス本体のHPは **Mod 内部の仮想HPプール** で管理し、ボスバーへ同期する（§8.3）。

### 2.3 10分想定の時間配分（1人換算）

10分 = 600秒に対して必要な「有効打撃時間」は 180秒 → **攻撃稼働率 30%** が設計目標。

| 区分 | 目安時間 | 比率 | 内容 |
|------|---------:|-----:|------|
| 有効打撃（クリ連打） | 180秒 | 30% | ボスの隙・追従成功中 |
| 追従・位置取り | 150秒 | 25% | ボス移動・突進後の再接近 |
| 回避 | 150秒 | 25% | テレグラフ付き攻撃の回避 |
| ギミック対応 | 60秒 | 10% | 全体ギミック、雑魚処理等（ボスへのダメージ不可） |
| ボス非接地／無敵演出 | ≦60秒 | ≦10% | 跳躍・フェーズ移行演出（§5で上限化） |

クリティカル失敗（地上打撃 8 ダメージ）や死亡・復帰を含めると 8.5〜11分に収まる想定。
**実測テレメトリ（§9）で稼働率を測り、HP ではなく攻撃パターンの隙で調整する**のが原則。

### 2.4 人数スケーリング

ボスは同時に1人しか狙えないため、人数が増えるほど「狙われていない人」の稼働率が上がる。単純な線形倍では短期化する。

```
HP(N) = HP_base × N × (1 + k × (N - 1))     k = 0.10 を初期値（テレメトリで調整）
```

| 人数 N | HP(N) | 備考 |
|-------:|------:|------|
| 1 | 3,456 | |
| 4 | 17,971 | |
| 8 | 47,001 | |
| 16 | 138,240 | 上限人数は要決定（§10） |

加えて、人数増加で稼働率が上がりすぎないよう **全体攻撃・分散ギミック** を各フェーズに最低1つ置く。
HP は戦闘開始時の参加人数で確定し、途中参加は「参加者として登録された人数」で再計算しない（荒らし防止）。

## 3. ダメージ受付ポリシー（P3〜P6 の実装方針）

### 3.1 拒否リストではなく **許可リスト** 方式

「メイス・矢・ポーション・トライデントを弾く」を個別に書くと、TNT・エンドクリスタル・溶岩・棘の鎧・狼・火炎エンチャント・ウィンドチャージ・雪玉・リスポーンアンカー等の抜け道が残る。
そこで **「受け付けるダメージ」だけを定義し、それ以外はすべて 0** にする。

受付条件（すべて満たす場合のみ）:

1. `DamageSource` の種類が `minecraft:player_attack`
2. `source.getEntity()` と `source.getDirectEntity()` が同一のプレイヤー（＝近接直接攻撃）
3. 使用武器 `source.getWeaponItem()` がタグ `raidboss:allowed_weapons` に含まれる（剣・斧。**メイス・トライデントは含めない**）
4. 攻撃者がレイド参加者として登録済み・アリーナ内にいる

例外: `/kill` 等の管理用（`BYPASSES_INVULNERABILITY`）のみ通す。

| 前提 | 許可リストでの扱い |
|------|------------------|
| P3 メイス | 武器タグに含めない（通常打撃もスマッシュ攻撃も 0）|
| P4 矢 | `player_attack` ではない（`arrow`）→ 0。クロスボウ・花火も同様 |
| P4 ポーション | `magic`/`indirect_magic` → 0。状態異常は §3.3 で別途遮断 |
| P5 トライデント | 投擲は `trident` → 0。手持ち近接は武器タグ外 → 0 |
| その他 | 爆発・火・溶岩・落下・窒息・棘・ペット・ゴーレム・召喚物 → すべて 0 |

### 3.2 1撃上限とエンチャント方針

基準は「エンチャント無し」だが、実サーバーではシャープネス・力のポーションが持ち込まれる。

| 状態 | 1撃（クリ） | DPS 比 |
|------|----------:|------:|
| 無エンチャ | 12 | 100% |
| シャープネスV（+3, クリ倍率対象外） | 15 | 125% |
| 力II（攻撃力+6）+ シャープネスV | 24 | 200% |

推奨: **1撃上限 = 15**（＝シャープネスV＋クリ）。エンチャントには報酬感を残しつつ、力ポーション等で戦闘時間が半減するのを防ぐ。
（代替案: 武器の基礎攻撃力のみで計算し直して完全正規化する。§10 で決定）

### 3.3 無敵時間（i-frame）の扱い ― マルチで最重要

バニラの `LivingEntity` は被弾後 10 tick の間、**直前より大きいダメージの差分しか通さない**。
このままだと複数人の同時攻撃がほぼ吸収され、人数を増やしても DPS が伸びない。

- ボス側のグローバル無敵時間は **0** にする
- 代わりに **攻撃者ごとの無敵時間 10 tick** を持つ（剣のクールダウン 12.5 tick より短いので正規の攻撃は損しない）
- スイープ攻撃・マルチパート判定による 1振り多段ヒットはこれで防げる

### 3.4 状態異常無効（P6）

- `canBeAffected(MobEffectInstance)` を常に `false`（ポーション・ウィザー・毒・鈍足・発光すべて）
- 炎上: 状態異常ではないが「火炎エンチャントで炎上ダメージ」を避けるため `fireImmune()` を付与（ダメージは許可リストで既に 0）
- 凍結（粉雪）: アリーナに粉雪が存在しないため不要だが `canFreeze()=false`
- ノックバック: ノックバック耐性 1.0 ＋ `knockback()` を無効化（ウィンドチャージ・ノックバックエンチャント・爆風押し出し対策）

### 3.5 位置操作の無効化（接地公平性の裏側）

ボスを「浮かせる・運ぶ・閉じ込める」手段を全て潰す。

| 手段 | 対策 |
|------|------|
| ボート・トロッコに乗せる | `canRide()=false`、加えて§4で設置自体を禁止 |
| リード | `canBeLeashed()=false` |
| 釣り竿で引き寄せ | 釣り針の引き寄せ対象外にする |
| 爆風・ウィンドチャージで吹き飛ばし | `ignoreExplosion()=true`、押し出し無効 |
| 他エンティティによる押し出し | `isPushable()=false` |
| 透明化でターゲット切り | ターゲット判定で透明化を無視 |

## 4. 戦闘ワールド（アリーナ次元）のルール（P7）

### 4.1 二重防御

1. **ゲームモードで止める**: アリーナ入場時に参加者を Adventure モードへ（退出時に元へ戻す）。ブロック設置・破壊・大半の `useOn` 系アイテム（バケツ・エンドクリスタル・防具立て等）が止まる。
2. **イベントで止める**（OP・クリエイティブ・Adventure の穴対策）:

| 対象 | 処置 |
|------|------|
| ブロック設置／破壊 | キャンセル（アリーナ次元全域）|
| バケツ（水・溶岩・粉雪）、火打石、ファイヤーチャージ、骨粉 | 使用キャンセル |
| ボート・トロッコ・防具立て・エンドクリスタル・スポーンエッグ | 使用キャンセル |
| **エンティティ出現の全体フィルタ** | アリーナ次元に入るエンティティを許可リスト（プレイヤー／ボス／ボスの召喚物と弾／ドロップ品／経験値）で判定し、それ以外の出現をキャンセル。上の個別対策の取りこぼしを最後に止める網 |

### 4.2 移動手段の対称性

ボスは接地を強制されるので、プレイヤー側の空中機動も制限するのが公平。

| 手段 | 推奨 | 理由 |
|------|------|------|
| エリトラ＋ロケット | 禁止 | 無限滞空で回避ギミックが無意味化 |
| トライデント（激流） | 禁止 | 同上（ダメージ無効なので所持価値も無い）|
| エンダーパール・コーラスフルーツ | 禁止（または長めのクールダウン）| ギミック範囲外への瞬間退避 |
| ウィンドチャージ（自己打ち上げ） | 禁止 | 空中時間の延長 |
| 盾・不死のトーテム・金リンゴ | 許可（トーテムは個数制限を検討）| 防御側の選択肢として残す |

### 4.3 地形

- 平坦な円形アリーナ（半径 32〜48 ブロック目安）、液体なし、段差は 1 ブロック以内
- アリーナ外周に「戻し」判定（ボスがリーシュ半径を越えたら中央へ帰還、プレイヤーは押し戻し）
- 天井高は ボス跳躍最高点＋余裕（プレイヤーが天井で滞空を稼げない高さ）

## 5. 接地公平性ルール（P8）

プレイヤーの攻撃手段は近接のみ。**ボスが空中にいる時間 ＝ 誰も攻撃できない時間** になる。

| ルール | 値（初期案） |
|--------|-------------|
| 1回の非接地時間の上限 | 30 tick（1.5秒）。超過したら強制落下 |
| 戦闘全体の非接地率 | ≦ 10%（テレメトリで監視）|
| 跳躍攻撃の着地点 | 必ずアリーナ内の地面。着地後に **2〜3秒の硬直（反撃窓）** を必ず付ける |
| 「空中フェーズ」 | 使う場合は1回 ≦ 8秒、その間はボスが **無敵扱い** でなく「到達不能」なだけなので、プレイヤー側の回避ギミックに置き換える。時間は §2.3 の「非接地」枠から支出 |
| 飛行・浮遊・壁登り | 禁止（`noGravity` を使わない）|
| 当たり判定 | プレイヤーのリーチ 3 ブロックで胴体に届く高さに設計（例: 幅 2.0 × 高さ 3.5）|

## 6. 攻撃設計ガイドライン

### 6.1 テレグラフ（予兆）とラグ

マルチサーバーでは 100〜200 ms の遅延を前提とする。

| 攻撃区分 | 予兆時間 | 予兆表現 |
|---------|---------|---------|
| 軽攻撃 | ≧ 0.6秒 | 振りかぶりモーション＋効果音 |
| 重攻撃 | ≧ 1.0秒 | 地面パーティクルで範囲表示 |
| 全体ギミック | ≧ 2.0秒 | ボスバー色変化＋タイトル表示＋範囲表示 |

- 判定は **サーバー側のみ**。範囲表示とダメージ判定の形は完全一致させる
- 「ジャンプで避けられる地面衝撃波」はクリティカルのジャンプ周期と噛み合う良い題材。ただし **ジャンプ中の人だけ当たる攻撃** は近接職を一方的に不利にするので作らない

### 6.2 被ダメージ基準（プレイヤー側）

ネザライト防具一式（防御 20・タフネス 12・エンチャ無し）での実被ダメージ:

| ボスの攻撃値 | 実被ダメ | 体力20に対する割合 |
|------------:|--------:|------------------:|
| 10 | 2.8 | 14% |
| 15 | 4.8 | 24% |
| 25 | 10.0 | 50% |
| 40 | 20.8 | 即死 |

ダメージ軽減エンチャントIV×4（-64%）を入れると攻撃値 40 でも 7.5 まで下がる。装備差で難易度が激変するため:

- **通常攻撃**: 防具計算に従う（装備の価値を残す）。攻撃値 10〜25
- **ギミック攻撃**（回避すべきもの）: 防具・エンチャ軽減を貫通する独自ダメージタイプで **体力の割合ダメージ**（例: 最大体力の 60%）

### 6.3 反撃窓（Punish Window）

稼働率 30% を作る主役。重攻撃・跳躍の後に必ず「接地・静止・弱点露出」の時間を置く。

| 行動 | 反撃窓 |
|------|-------|
| 重攻撃の空振り | 1.5秒 |
| 跳躍着地 | 2.0秒 |
| 全体ギミック成功時 | 4〜6秒（ダウン）|

### 6.4 フェーズ構成テンプレート

| フェーズ | HP範囲 | 狙い |
|---------|--------|------|
| P1 | 100〜70% | 基本行動の学習。単体攻撃中心 |
| P2 | 70〜35% | 全体ギミック追加、移動速度上昇 |
| P3 | 35〜0% | 行動間隔短縮、反撃窓は維持（短くしない）|
| 激昂 | 開始15分経過 | 被ダメ増加の全体攻撃連発（実質タイムリミット）|

フェーズ移行演出の無敵は 1 回 ≦ 3秒。

## 7. セッション管理

| 項目 | 方針 |
|------|------|
| 参加登録 | アリーナ入場時に登録、開始後 30 秒で人数確定 → HP 決定 |
| 死亡 | アリーナ入口でリスポーン、復帰まで 10 秒。デス回数上限は任意 |
| 全滅・全員離脱 | 30 秒誰もいなければボスはリセット（HP 全回復・位置初期化）|
| ログアウト | 参加者扱いは維持、5 分戻らなければ報酬対象外 |
| 報酬資格 | 与ダメージ割合 ≧ 2% もしくは ギミック成功 1 回以上（放置対策）|
| スタック対策 | ボスが 5 秒間移動不能 → 最寄りの有効地点へテレポート |

## 8. 実装構造（NeoForge 1.21.1 想定）

### 8.1 ローダー選定

NeoForge を推奨する理由: ブロック設置・アイテム使用・エンティティ出現（`EntityJoinLevelEvent`）など、§4 で必要な **キャンセル可能イベントが標準で揃っている**。
Fabric の場合は `UseBlockCallback` / `UseItemCallback` / `PlayerBlockBreakEvents.BEFORE` 等で大半をカバーでき、エンティティ出現の遮断のみ Mixin が必要。

> 1.21.2 以降は `hurt()` が `hurtServer(ServerLevel, DamageSource, float)` に変わる等、API 差分があるので版は早めに固定する。

### 8.2 モジュール構成

```
raidboss/
├─ core/
│  ├─ AbstractRaidBoss          … 全ボス共通（§3 を実装）
│  ├─ BossDamagePolicy          … 許可リスト判定・1撃上限・攻撃者別i-frame
│  ├─ VirtualHealthPool         … 仮想HP・ボスバー同期
│  ├─ GroundingGuard            … 非接地時間の監視と強制落下（§5）
│  └─ PhaseController           … HP閾値でフェーズ遷移
├─ combat/
│  ├─ AttackPattern             … 予兆→判定→反撃窓 の状態機械
│  ├─ Telegraph                 … 範囲表示パーティクル（判定形と共有）
│  └─ RaidDamageTypes           … 防具貫通の割合ダメージ（datapack 定義）
├─ arena/
│  ├─ ArenaDimension            … dimension_type / 平坦チャンク生成
│  ├─ ArenaRules                … 設置・使用・出現の各イベント遮断（§4）
│  └─ ArenaBounds               … リーシュ・押し戻し
├─ session/
│  ├─ RaidSession               … 参加者・人数確定・リセット・報酬
│  └─ Telemetry                 … 稼働率・非接地率・討伐時間のログ
└─ data/                         … ボス定義 JSON（HP倍率・攻撃リスト・フェーズ）
```

### 8.3 共通ボスの要点（擬似コード / Mojang マッピング）

```java
public abstract class AbstractRaidBoss extends PathfinderMob {
    private final VirtualHealthPool pool;        // 3,456 × スケーリング
    private final Object2LongMap<UUID> lastHitTick = new Object2LongOpenHashMap<>();

    @Override
    public boolean hurt(DamageSource src, float amount) {
        if (src.is(DamageTypeTags.BYPASSES_INVULNERABILITY)) return super.hurt(src, amount);
        if (!BossDamagePolicy.isAllowed(src, session)) return false;   // §3.1

        ServerPlayer p = (ServerPlayer) src.getEntity();
        long now = level().getGameTime();
        if (now - lastHitTick.getOrDefault(p.getUUID(), Long.MIN_VALUE) < 10) return false; // §3.3
        lastHitTick.put(p.getUUID(), now);

        float dealt = Math.min(amount, BossDamagePolicy.MAX_HIT);       // §3.2
        pool.damage(dealt, p);                                          // 仮想HP・貢献度記録
        this.invulnerableTime = 0;                                      // グローバルi-frameを使わない
        playHurtFeedback();
        if (pool.isDepleted()) die(src);
        return true;
    }

    @Override public boolean canBeAffected(MobEffectInstance e) { return false; }  // P6
    @Override public boolean isPushable() { return false; }
    @Override public boolean canBeLeashed() { return false; }
    @Override protected boolean canRide(Entity vehicle) { return false; }
    @Override public boolean ignoreExplosion(Explosion e) { return true; }
    @Override public void knockback(double s, double x, double z) { }
}

public final class BossDamagePolicy {
    public static final float MAX_HIT = 15.0f;

    public static boolean isAllowed(DamageSource src, RaidSession session) {
        if (!src.is(DamageTypes.PLAYER_ATTACK)) return false;                 // 矢・ポーション・投擲トライデント・爆発等
        if (!(src.getEntity() instanceof ServerPlayer p)) return false;
        if (src.getDirectEntity() != p) return false;                         // 間接攻撃の排除
        ItemStack weapon = src.getWeaponItem();
        if (weapon == null || !weapon.is(RaidTags.ALLOWED_WEAPONS)) return false; // メイス・トライデント近接
        return session.isParticipant(p) && session.arena().contains(p);
    }
}
```

`raidboss:allowed_weapons`（item tag）初期値: `#minecraft:swords`, `#minecraft:axes`

## 9. 調整のためのテレメトリ

討伐ごとに記録し、§2.3 の配分と実測を比べて調整する。

| 指標 | 目標 |
|------|------|
| 討伐時間 | 8.5〜11分 |
| 参加者平均の攻撃稼働率 | 25〜35% |
| ボス非接地率 | ≦ 10% |
| クリティカル率 | 参考値（低すぎれば反撃窓が短い）|
| フェーズ別の死亡数 | 特定攻撃への偏りを検出 |
