# 塗り絵の描き方（Windows のペイントだけで足りる）

立体を扱う道具は要らない。**箱の形・向き・UV は骨格データから自動生成してある**ので、
描く側の仕事は `assets/minecraft/textures/item/knight/*.png` を**塗り替えるだけ**である。

---

## 1. 何を塗るのか

11枚ある。**各 32×32**。左右の腕・角・肩、両形態の同じ部位は1枚を共有する（寸法差は UV の伸びに吸収させる）。

| ファイル | 貼られる部位 | 枠の並び | 前面の枠 | 頭文字 |
|---|---|---|---|---|
| `torso.png` | 第一形態の胴・第二形態の人胴 | 縦積み | 11×12 | 6/6 |
| `head.png` | 頭（両形態） | 縦積み | 11×10 | 6/6 |
| `horn.png` | 左右の角（両形態） | 横並び | 4×28 | **0/6** |
| `crest.png` | 頭飾り（両形態） | 縦積み | 11×10 | 6/6 |
| `shoulder.png` | 左右の肩（両形態） | 縦積み | 13×9 | 6/6 |
| `arm.png` | 左右の腕（両形態） | 横並び | 8×21 | 6/6 |
| `leg.png` | 第一形態の左右の足 | 横並び | 8×22 | 6/6 |
| `spear.png` | 槍の柄（両形態） | 横並び | 5×27 | **4/6** |
| `spearhead.png` | 穂先（両形態） | 縦積み | 11×10 | 6/6 |
| `horse_body.png` | 馬胴 | 縦積み | 7×6 | **2/6** |
| `horse_leg.png` | 馬の前足・後足 | 横並び | 7×25 | 6/6 |

「頭文字」は面の目印（F/B/R/L/U/D）が入った枠の数である。**枠が狭くて入らないものは
`templates/guide/` の4倍の拡大図で読む**（次の節）。

### 塗る細かさ

1ブロックあたりの画素数で見る。**バニラのブロックは16画素**である。

| 部位 | 1ブロックあたり | |
|---|---|---|
| 穂先・角 | 26〜39画素 | バニラより細かい |
| 頭・肩・腕・足・頭飾り | 15〜22画素 | ほぼバニラと同じ |
| 胴・人胴 | 10〜11画素 | **バニラより粗い** |
| 槍 | 7〜8画素 | **バニラより粗い**（一様な柄なので目立ちにくい） |
| 馬胴 | 6〜7画素 | **最も粗い**（2.6ブロックの奥行に対し画布が足りない） |

胴と馬胴を描き込みたくなったら、`SkinNet.CANVAS` を 64 か 128 にして生成し直せばよい
（UV は割合で書くのでモデルの JSON はそのまま通る）。**ただし塗った PNG は寸法が合わなくなり、
塗り直しになる。**

## 2. 枠の読み方

1枚の中に6つの枠がある。**枠の左上に面の頭文字が入っている**ので、並びを覚える必要はない。

| 文字 | 面 | 描く絵 |
|---|---|---|
| `F` | 前（Front） | 正面から見た絵。顔・胸の紋章はここ |
| `B` | 後（Back） | 背面から見た絵 |
| `R` | 右（Right） | **個体から見た右**。正面から見ると左側 |
| `L` | 左（Left） | 個体から見た左 |
| `U` | 上（Up） | 真上から見た絵。北（前方）が枠の上 |
| `D` | 下（Down） | 真下から見た絵 |

枠の中の向きは **その面を外から見たまま**である。前面の枠に顔を描けば前を向く。

**濃い灰色の余白はどの面にも貼られない。** 塗っても見た目に出ないし、塗らなくても問題ない。

枠の並べ方は画像によって2通りある（画素を大きく取れるほうを生成側が選ぶ）。

```
  横並び                          縦積み
       ┌────┬────┐               ┌────┬────┐
       │ U  │ D  │               │ U  │ D  │
  ┌────┼────┼────┼────┐          ├────┼────┤
  │ R  │ F  │ L  │ B  │          │ R  │ L  │
  └────┴────┴────┴────┘          ├────┼────┤
                                 │ F  │ B  │
                                 └────┴────┘
```

### 頭文字が入らない枠

32×32 では枠が狭く、`horn.png`（0/6）・`horse_body.png`（2/6）・`spear.png`（4/6）は
文字が入らない。**`templates/guide/` に4倍の拡大図がある**ので、塗るときはそちらを別の窓で
開いておく。中身は同じ割り付けで、文字だけ大きく描いてある。

```
resourcepack/templates/guide/horn.png     ← 128×128・文字あり（読む用）
resourcepack/templates/horn.png           ←  32×32・原本（戻す用）
resourcepack/assets/minecraft/textures/item/knight/horn.png   ← 32×32（塗る用）
```

**拡大図を塗ってはいけない。** 貼られるのは `textures/item/knight/` の側だけである。

## 3. ペイントでの手順

1. `E:\raid-dev\resourcepack\assets\minecraft\textures\item\knight\torso.png` を**右クリック → プログラムから開く → ペイント**
2. **表示 → ズーム**を 1600% まで上げる（32×32 は小さい）。**表示 → グリッド線**を入れると1画素が見える
3. 枠の中を塗る。下地は面ごとに明るさを変えてあるので、そのまま陰影として使ってよい
4. 元の色を拾いたいときは**スポイト**（色の選択）を使う
5. **Ctrl + S** で保存する。形式を訊かれたら **PNG のまま**にする

### 守ること

| 決め事 | 理由 |
|---|---|
| **画像の大きさ（32×32）を変えない** | 枠の座標が UV に焼き込まれている。サイズを変えると全部ずれる |
| **PNG 以外で保存しない** | JPEG は色がにじみ、BMP は Minecraft が読まない |
| **透明を使わない** | 古いペイントは α を残せない。箱は不透明で描く |
| **ファイル名を変えない** | モデルの `"skin"` がこの名前を指している |
| **`textures/item/knight/` から動かさない** | `elements` を持つモデルのテクスチャは**ブロックアトラス**に縫い込まれる。既定の取り込み元は `textures/block/` と `textures/item/` だけで、その外に置くと**紫と黒の欠損**になる |

> Windows 11 のペイント（レイヤー・透明あり）でも構わない。透明部分は黒くなるだけで壊れはしない。

### 原本に戻す

塗り直しに失敗したら `resourcepack/templates/` から同じ名前の PNG を写せばよい。
こちらは生成のたびに書き直される原本である。

```powershell
Copy-Item -Force E:\raid-dev\resourcepack\templates\torso.png `
                 E:\raid-dev\resourcepack\assets\minecraft\textures\item\knight\torso.png
```

## 4. 塗った絵を確かめる

塗るのは**リポジトリの中のファイル**である。塗ってから同期する。

```powershell
cd E:\raid-dev
git pull                                      # 生成物が更新されている場合がある
# ペイントで assets\minecraft\textures\item\knight\*.png を塗る
powershell -ExecutionPolicy Bypass -File E:\raid-dev\resourcepack\sync-pack.ps1
```

ゲーム内で:

```
F3 + T                  # リソースパックを読み直す
/raid model authored    # 描いたモデルで出し直す
/raid model vanilla     # バニラの素材と見比べる
/raid model             # いまどちらかを表示する
```

**絵を直しただけなら `F3 + T` で足りる。** 表示エンティティはクライアント側で描き直されるので、
個体を消す必要もサーバーを再起動する必要もない。`/raid model authored` は<b>方式を切り替える</b>
ときだけ必要で、すでに描いたモデルで出ているなら打たなくてよい。

| 直したもの | 必要な操作 |
|---|---|
| **テクスチャ（PNG）** | 同期 → `F3+T` |
| モデルの JSON（`generate-pack.sh` の出力） | 同期 → `F3+T` |
| 見た目の方式を切り替える | `/raid model authored` / `vanilla` |
| 骨格の寸法・モーション（`KnightDefinition`） | jar をビルド → サーバー再起動 → `/raid spawn` |

シンボリックリンク（`README.md` の方法B）で置いている場合は、**同期も要らず `F3+T` だけ**である。

`/raid model authored` は**出ている個体をその場で作り直す**。骨格は個体を作るときに組むため、
方式の切り替えは出し直さないと効かない。サーバーを起動し直すとバニラの素材に戻る（既定値）。

塗った絵は**リポジトリに入れて残す**。手元だけに置くと、生成し直したときや環境を移したときに失う。

```powershell
git add resourcepack/assets/minecraft/textures/item/knight
git commit -m "騎士の塗り絵を描く"
git push
```

参加者へ配る段（zip と `server.properties`）は `README.md` の「本番で配る」を見ること。

## 5. うまくいかないとき

| 症状 | 原因 |
|---|---|
| 生成時に「大きさが画布と違う」と出る | 画布の設定を変えた。その PNG を消して置き直す（塗り直しになる） |
| 紙のまま出る | リソースパックが読み込まれていない。`README.md` の「効いていないときの切り分け」を見る |
| 紫と黒の欠損 | テクスチャが見つからない（`textures/item/knight/` の外に置いた・ファイル名が違う）か、モデルの JSON が壊れている。`./core/generate-pack.sh` で作り直す |
| 白いままで絵が出ない | `/raid model authored` を実行していない（バニラの素材が出ている） |
| 絵が伸びている | その部位は共有した1枚を使っている。寸法差を UV の伸びで吸収しているためで、異常ではない |
| 絵が上下逆・左右逆 | 枠を取り違えている。目印の文字（F/B/R/L/U/D）で読み直す |
| 塗った絵が消えた | 生成では消えない。`templates/` から写し戻して塗り直す |

---

## 6. 生成し直すとき

骨格の寸法（`KnightDefinition`）を変えたら作り直す。

```sh
./core/generate-pack.sh
```

- モデルの JSON と振り分け、`templates/` の原本と拡大図は**上書きされる**
- `assets/minecraft/textures/item/knight/*.png` は**触らない**（塗った絵を消さない）
- 塗った PNG の大きさが画布と違うときは警告を出す（貼る位置が黙ってずれるため）

寸法を変えると枠の大きさも変わるため、絵は伸び縮みする。大きく変えたときは
`templates/` の新しい原本と見比べて塗り直すのが早い。
